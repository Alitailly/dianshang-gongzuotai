# 04 · 店铺接入与正式表格迁移

> 定档版（2026-08-19）。开发人员照做即可。

## 1. 接入新店铺（美客多账号）

> 架构已支持多店铺：配置一店一文件，全链路自动发现（后端/看板/飞书**无写死店名**）。

### 步骤

```bash
# ① 复制模板（文件名即店铺配置名，建议全小写，如 xw07）
cp stores.d/store.example.env stores.d/<店名>.env

# ② 编辑 stores.d/<店名>.env，填入：
#    STORE_NAME=显示名          → 飞书表名、看板下拉显示用（如 XW07）
#    CLIENT_ID / CLIENT_SECRET  → 该美客多卖家账号绑定的应用凭证
#    REDIRECT_URI               → 保持 https://www.google.com
#    ML_SITE_ID=MLB             → 站点：MLB(巴西)/MLM(墨西哥)/MLA(阿根廷)/MLC(智利)…

# ③ OAuth 授权（浏览器完成，自动写回 ACCESS_TOKEN/REFRESH_TOKEN）
.venv/bin/python -m src.oauth_authorize <店名>

# ④ 重启后端（使其出现在 /api/stores 与看板下拉）
# ⑤ 触发同步验证（或等定时任务自动跑）
curl -X POST "http://127.0.0.1:8000/api/sync"
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily"
# ⑥ 校验飞书
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily/verify"
```

之后 token 到期由 `Store.refresh_token()` **自动刷新并写回 env 文件**，无需人工。

### 注意

- ⚠️ **站点时区**：广告定档/日期口径目前按**巴西时间**（`src/timeutil.py`，UTC-3）。
  若新店是**非巴西站**（墨西哥/阿根廷…），定档时间点与"昨天/今天"口径要按该站点时区调整
  （改造方案：`timeutil` 支持按 `ML_SITE_ID` 配置时区，需要时找后端改）。
- ⚠️ **凭证安全**：`stores.d/*.env` 含 token，已加入 `.gitignore`（勿提交）。
- 佣金率/平台运费/费率按 `store.site_id` 动态获取（listing_prices 按站点），对新店通用。

## 2. 测试飞书 base → 正式飞书 base 迁移

> 当前 `feishu.env` 指向**测试 base**。数据都在本地 SQLite，飞书只是展示层，迁移无需搬数据、无风险。

### 前置

1. 在飞书建**正式多维表格**（或让管理员开一个空 base）。
2. 飞书开放平台：给应用开启 `bitable:app` 权限并**发布新版本**（如已开通可跳过）。

### 迁移步骤

```bash
# ① 备份
cp feishu.env feishu.env.bak

# ② 修改 feishu.env，只改一个值：
#    FEISHU_APP_TOKEN=正式base的app_token
#    （APP_ID/APP_SECRET 不变；TABLE_ID 是旧表 ID，可留，同步会按表名自动重建）

# ③ 重启后端
# ④ 全量同步（自动在正式 base 重建全部月份子表 + 字段 + 数据）
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily"
# ⑤ 校验
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily/verify"
#    期望：0 缺失 / 0 多余 / 0 值差
```

### 迁移后收尾

- 正式 base 确认无误后，**测试 base 的表可留可删**（保留则不影响；删除注意一个 base 至少要留 1 个子表）。
- 若正式 base 需要**不同的表名/列**，改 `backend/app/routers/bitable.py` 的 `FIELD_DEFS` 后重跑同步即可（幂等）。
- 迁移后继续用 `docs/05-部署与运维.md` 的校验命令定期抽查。

## 3. 回滚

- 改回 `feishu.env.bak`（测试 base token）→ 重启 → 重跑同步即可切回测试 base。
- SQLite 数据本身不受飞书侧任何操作影响。
