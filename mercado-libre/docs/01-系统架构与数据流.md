# 01 · 系统架构与数据流

> 定档版（2026-08-19）。面向开发人员：数据从哪来、存哪、怎么流到看板和飞书。

## 1. 三层架构

```
┌────────────────────────────────────────────────────────────────────┐
│ ① 数据源层  Mercado Libre API（每店铺一个 OAuth 应用）              │
│    src/store.py / auth.py / client.py / atoms/{products,orders}.py │
└───────────────┬────────────────────────────────────────────────────┘
                │ 拉取（手动 / 定时增量）
┌───────────────▼────────────────────────────────────────────────────┐
│ ② 存储层  SQLite（backend/app/db.py）                              │
│    product_variation  商品当前元数据（每变体一行，同步时全量刷新）    │
│    daily_snapshot     每日快照（商品×日期：广告+订单聚合，upsert）   │
└───────┬───────────────────────────────┬────────────────────────────┘
        │ 查询（repository.py + routers） │ 导出（routers/bitable.py）
┌───────▼──────────────┐      ┌──────────▼───────────────────────────┐
│ ③a Web 看板（Vue3）  │      │ ③b 飞书多维表格（Bitable）            │
│    商品分析/广告/订单 │      │    每 店铺×月份 一个子表              │
│    http://localhost:5173 │   │    行 = 商品×日期（38→33 列）        │
└──────────────────────┘      └──────────────────────────────────────┘
```

## 2. 存储层表结构

### product_variation（商品当前元数据，同步时全量 DELETE+INSERT）

```
store, item_id, variation_id, title, seller_sku, gtin,
price(现价=促销价), available_quantity, currency_id,
performance_score, performance_level, has_ads,
original_price, sale_price, promotion_type,
platform_shipping, status, listing_type, free_shipping,
official_fee_rate(官方精确佣金率), shipping_payer, date_created(上架日),
attributes, updated_at
```

主键语义：`(store, item_id, variation_id)`。变体多行；飞书/看板聚合按 `(store, item_id)`。

### daily_snapshot（每日快照，主键 `(store, item_id, date)`，增量 upsert）

```
ad_cost, ad_clicks, ad_impressions, ad_ctr, ad_sales, ad_roas, ad_acos,   -- 广告（按天）
sold_quantity, revenue, commission, shipping_fee, order_count,            -- 订单（按天聚合）
unit_price, full_unit_price, coupon_amount, gross_amount                  -- 订单级价格信息
```

### daily_stock（每日商品状态快照，主键 `(store, item_id, date)`，每天同步时写入"当天"值）

```
available_quantity(库存), price(现价), original_price, performance_score,
has_ads, variation_count, official_fee_rate, listing_type,
platform_shipping, shipping_payer
```

> 用途：ML 不提供历史库存/价格，本表从启用日起记录**每天**的商品聚合状态；
> 飞书历史行优先取本表"当天值"，无快照的日子回退 `product_variation` 当前值（聚合口径与飞书子查询一致）。

## 3. 关键模块职责

| 模块 | 职责 |
|---|---|
| `src/timeutil.py` | 巴西时区（UTC-3）；广告定档规则 `br_latest_finalized_date()`（10:00 前=前天，10:00 后=昨天） |
| `backend/app/sync.py` | ML→SQLite：`run_sync(days_back=N)`；`daily_snapshot` 用 `INSERT … ON CONFLICT DO UPDATE`（**已定档历史不重写、不丢失**） |
| `backend/app/repository.py` | 看板商品列表查询 + 指标计算（`_compute_ratios`） |
| `backend/app/feishu.py` | 飞书 Bitable 底层：token（2h 缓存）/ 表 / 字段 / 记录（batch ≤500） |
| `backend/app/routers/bitable.py` | 飞书每日同步：`_daily_rows`（组装行）→ `_attach_daily_visits` → `_derive_metrics` → `_upsert` |
| `backend/app/main.py` | APScheduler：每日三个时间点（北京 08:50 / 13:50 + 巴西 10:20）+ 开机补跑（`data/.daily_update_marker`） |

## 4. 时区与定档规则（贯穿全局）

- 所有"天"按**巴西时间 UTC-3** 统计（`br_date_str` / `br_days_ago`）。
- **广告 T+1**：次日巴西 10:00 定档；定档前数据不完整。`br_latest_finalized_date()`（此表由代码生成，勿手改）：

<!-- GEN:finalized_rule:BEGIN -->
| 当前巴西时间 | 广告定档截止日 |
|---|---|
| < 10:00 | 前天 |
| ≥ 10:00 | 昨天 |
<!-- GEN:finalized_rule:END -->

- 飞书行「广告状态」：`日期 ≤ 定档截止日` → `已定档`（广告列正常填）；否则 → `未定档·广告预览`（**广告列显式置空**，只保留实时数据）。

## 5. 新店铺接入（自动发现）

- 配置：`stores.d/<店名>.env`（模板 `stores.d/store.example.env`）→ `list_stores()` 自动发现。
- 后端/看板/飞书**无任何写死店名**：`run_sync()` 遍历所有店；飞书自动建「店铺 YYYY年M月」表。
- 完整步骤见 `docs/04-店铺接入与正式表格迁移.md`。
