# 看板设计（仿蓝鲸BI）— v1

> 目标：把当前两页（经营总览 / 商品分析）按蓝鲸 `#/index` 与 `#/listing` 的布局与信息架构重构。
> 本设计只定「布局/区块/卡片」，**筛选交互后续单独做**（时间范围已有，先保留）。

## 1. 数据链路速查（每列怎么来的）

| 列 | 同步时（写库） | 查询时 |
|---|---|---|
| 商品/店铺/商品ID/变体/价格/可售库存 | `GET /items/{id}`（标题/变体数组/价格/库存）→ product_variation | SQLite |
| 体验分 | `GET /item/{id}/performance` → product_variation | SQLite |
| 广告(有无) | `GET .../ads/search`（近30天）→ has_ads | SQLite |
| 已售/销售金额/平台佣金 | `GET /orders/search`（按天聚合）→ daily_snapshot | SUM（整个所选区间） |
| 物流支出 | `GET /shipments/{id}/costs`（senders[].cost）→ daily_snapshot | SUM |
| 广告花费/点击/曝光/广告销售额 | `GET .../ads/search`（按天×90）→ daily_snapshot | SUM（**至定档截止日**） |
| 结算金额 | — | 计算：收入−佣金−物流 |
| CTR/ROAS/ACOS | — | 计算：clicks/prints×100、sales/cost、cost/sales×100 |
| 访客 | —（不做按天） | 实时 `GET /items/{id}/visits?date_from=&date_to=`（并发+缓存） |

## 2. 整体框架（沿用现有，微调）

- 左侧菜单：经营总览 / 商品分析（后续再加 交易分析/广告流量/订单管理…仿蓝鲸菜单树）。
- 顶部栏：店铺筛选（全店铺/BA05/AW04）｜币种 BRL｜时间范围（已有）｜同步数据。
- 风格：Element Plus 浅色主题（主色 #409eff），卡片白底圆角 + 浅阴影，与蓝鲸观感一致。

## 3. 经营总览 v2（仿蓝鲸 #/index）

### 3.1 KPI 卡片行（6 张，每张 = 主值 + 昨日值 + 环比箭头▲▼）
| 卡片 | 主值 | 副值 | 环比口径 | 来源 |
|---|---|---|---|---|
| 总销售额(BRL) | 所选区间销售合计 | 昨日销售额 | 与上一等长区间比 | daily_snapshot |
| 总销量(件) | 所选区间销量合计 | 昨日销量 | 同上 | daily_snapshot |
| 结算金额(BRL) | 收入−佣金−物流 | 昨日结算 | 同上 | daily_snapshot |
| 访问量(次) | 所选区间访客合计 | 昨日访问量 | 同上 | 访客实时接口 |
| 动销率(%) | 有销量 listing / 在售 listing | 昨日动销率 | 同上 | snapshot + 元数据 |
| 广告花费(BRL) | 广告花费合计（至定档日） | 昨日广告花费 | 同上 | daily_snapshot |

环比颜色：上升=红▲、下降=绿▼（蓝鲸/国内 BI 习惯）——实现时可按喜好切。

### 3.2 店铺表现（仿蓝鲸 tab：卡片 + 表）
- 每店三张小卡片：**订单数 / 访问量 / 转化率**（转化率=订单数÷访问量）。
- 明细表：序号 | 店铺 | 销售额(BRL) | 订单数 | 访问量 | 转化率 | 广告花费。

### 3.3 销量 / 销售额 趋势图（按天，ECharts 折线+柱）
- 数据：daily_snapshot 按 `date` 聚合（新增 `GET /api/overview/trend?date_from=&date_to=`）。
- 仿蓝鲸 `storeOrderHourTrend` 的位置，我们做「按天」曲线（小时粒度数据不足）。

### 3.4 排行榜（仿蓝鲸 tabs：销量暴涨/暴跌榜 → 换成我们有的）
- Tabs：**销量 TOP10 / 销售额 TOP10 / 广告花费 TOP10 / ROAS TOP10**（取所选区间）。
- 行：排名 | 商品标题 | 店铺 | 指标值 | 占比。
- 数据：新增 `GET /api/rankings?type=&date_from=&date_to=`（复用 repository 聚合）。
