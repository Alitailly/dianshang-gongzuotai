# 看板设计 · 广告投放监控 + 决策辅助（#/adManage）

> 状态：**设计文档**（未实现）。基于 2026-08-17 实测：ads/search 可读 15 条投放，字段已确认。
> 定位：ML **Product Ads API 是只读监控**（官方文档原话 "monitor campaigns, ads, and metrics"），
> 无 create/update/budget 端点；本账号为**自动投放模式**（Automatic mode，无自定义 campaign）。
> 因此本页 = **只读监控 + 本地决策建议 + 手工操作登记**，不做 API 写操作。
> 不动已实现部分；与「广告流量页」分工：广告流量页看**按天效果趋势**（daily_snapshot），本页看**当前投放状态 + 逐个商品决策**。

---

## 0. 数据源（已实测确认 ✅）

| 来源 | 内容 | 说明 |
|---|---|---|
| `ads/search`（实时） | 当前投放的每个商品：`item_id`、`status`/`status_raw`(active=投放中 A / hold=暂停 S)、`campaign_id`、`ad_group_id`、`current_level`(green/newbie)、`buy_box_winner`、`deferred_stock`(缺货)、`has_discount`、`image_quality`、`recommended`、`logistic_type`、`listing_type_id`、`permalink`、`thumbnail`、`price`、metrics(cost/prints/clicks/ctr/roas/acos/total_amount/direct/indirect) | 实测 15 条：active 10 / hold 5；green 12 / newbie 3；Buy Box 全 False |
| 商品分析本地库（repository） | 保本ROAS、结算率、佣金、物流费（按所选区间） | 用于决策规则判断 |
| `ad_ops_log`（🆕 本地表） | 手工登记的后台操作（暂停/恢复/调价/加预算/优化…） | API 不能写，操作结果靠人工登记留痕 |

**口径**：metrics 统计区间沿用全局规则——广告只统计到**定档截止日**（`_ad_cap`），未定档日不计入；前端 date range 复用 `useDataRange`（含"广告统计至 …"提示）。

## 1. 页面布局（仿蓝鲸，与广告流量页同风格）

### 1.1 顶部 KPI 卡（8 卡，随筛选联动）

| 卡 | 计算 |
|---|---|
| 投放中商品 (个) | status=active 数 |
| 暂停商品 (个) | status=hold 数（点击可只看暂停） |
| 广告花费 (BRL) | Σ metrics.cost（截至定档日） |
| 广告销售额 (BRL) | Σ metrics.total_amount |
| ROAS | 销售额÷花费 |
| ACOS (%) | 花费÷销售额 |
| Buy Box 获得率 (%) | buy_box_winner=true 数 ÷ 投放数 |
| 保本 ROAS | 商品级 breakeven_roas（结算口径，近似） |

### 1.2 状态 Tab + 筛选

- Tab：**全部 / 投放中(active) / 暂停(hold)**
- 筛选行：店铺下拉（BA05/AW04）｜ 关键词（标题/商品ID/SKU）｜ 只显示需关注（有建议项）
- 默认排序：广告花费 desc

### 1.3 表格列（分组 + 折叠，同商品分析风格）

| 组 | 列 |
|---|---|
| 商品 | 商品（缩略图+标题+商品ID，标题可点开 permalink 新窗口） / 店铺 / 投放状态(badge：投放中=绿/暂停=灰) / 等级(current_level 映射：green=绿/newbie=橙) |
| 投放信息 | campaign_id / ad_group_id / Buy Box(✓/✗) / 缺货(✓/✗) / 带折扣(✓/✗) / 主图质量 / listing 类型 |
| 效果 | 曝光 / 点击 / CTR% / 花费 / 广告销售额 / ROAS / ACOS / 保本 ROAS |
| 决策 | **建议**（文本+色标） / 最近操作（类型+时间）/ **操作**（登记按钮） |

### 1.4 决策建议规则（本地计算，前端标色 + 后端一并返回）

| 条件（区间内） | 建议 | 色 |
|---|---|---|
| `deferred_stock`=true | 缺货，建议暂停 | 红 |
| 花费>0 且 ROAS<保本ROAS | 亏损投放（广告吃利润），建议暂停或降价 | 红 |
| 花费=0 且 status=active | 无消耗，检查出价/是否真在展示 | 橙 |
| `buy_box_winner`=false | 未拿到 Buy Box，检查价格/物流竞争力 | 橙 |
| `current_level`=newbie | 新手期，先观察转化再调 | 橙 |
| 花费>0 且 ROAS≥保本ROAS×1.5 | 健康投放，可考虑加预算 | 绿 |
| `image_quality` 非 good | 主图质量差，优化主图 | 灰 |
| 其余 | 正常，暂不干预 | — |

多条命中取最严重一条。建议文案在**前端**渲染（规则集中在 `frontend/src/views/AdManage.vue` 常量表），后端只返回原始字段+保本ROAS，避免后端规则和展示耦合。

## 2. 操作登记（✋ 手工，因为 API 不能写）

### 2.1 交互
- 每行"登记"按钮 → 弹窗：操作类型下拉（**暂停投放 / 恢复投放 / 调整出价 / 调整预算 / 优化Listing / 其他**）+ 备注（必填，如"ROAS<保本，暂停3天"）+ 商品信息只读展示 → 保存。
- 保存后写 `ad_ops_log`，行内"最近操作"立即刷新；可点"历史"看该商品全部登记。

### 2.2 数据表（新增）

```sql
CREATE TABLE ad_ops_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  store TEXT NOT NULL,
  item_id TEXT NOT NULL,
  campaign_id TEXT,
  ad_group_id TEXT,
  op_type TEXT NOT NULL,   -- pause / resume / change_bid / change_budget / optimize / other
  note TEXT NOT NULL,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_adops_item ON ad_ops_log (item_id);
CREATE INDEX idx_adops_store ON ad_ops_log (store);
```

### 2.3 说明
- 登记**不调 ML API**，纯本地留痕，作用：① 决策建议可以"记忆"上次操作（如"已登记暂停，若恢复请登记恢复"）；② 多店铺操作历史可查。
- 登记后建议区若命中间隔时间短（如同日已登记暂停），提示"今日已登记 X"。

## 3. 后端接口（新增 `routers/ad_manage.py`，main.py 挂载）

| 接口 | 说明 |
|---|---|
| `GET /api/ad-manage/items?store=&keyword=&status=&attention=&sort_by=&order=&page=&page_size=&date_from=&date_to=` | 实时拉两店 ads/search（合并去重）→ 与 repository 商品级（保本ROAS/结算率/佣金/物流）按 item_id JOIN → 拼最近操作 → 分页返回。**带 5 分钟 TTL 缓存**（ads/search 每次打开实时拉，15 条/店很快） |
| `GET /api/ad-manage/summary?...` | 8 个 KPI（基于 items 同一份数据算，保证口径一致） |
| `POST /api/ad-manage/ops` | 登记操作 {store,item_id,campaign_id,ad_group_id,op_type,note} |
| `GET /api/ad-manage/ops?item_id=&store=` | 某商品/店铺的操作历史 |

**ads/search 拉取实现**：`src/atoms/products.py` 新增 `get_product_ads(store, date_from, date_to)`（复用 `get_ads_by_item` 的分页逻辑，但保留全部管理字段、不丢 status/campaign 等）；对每个 store 并发拉取（2 店并行）。日期上限 = `_ad_cap(date_to)`（定档规则）。

## 6. 风险与待实测 ⚠️
- `status_raw` 枚举只见到 A(active)/S(hold)：`S` 是否=手动暂停还是系统暂挂未确认 → 前端把 hold 显示为"暂停"并标注"含系统暂挂"，后续观察。
- ads/search 是否含"从未投放"的商品：实测只返回**当前有投放记录**的 15 条 → 表格只显示投放中商品，"全部商品 vs 未投放商品"对比不在本页（商品分析已有 has_ads 列）。
- metrics 按 `date_from/date_to` 传参实时返回，T+1 定档日之前的值可能波动 → 统计上限强制 `_ad_cap`，与全站一致。
