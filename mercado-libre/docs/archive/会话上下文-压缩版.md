## 2. 关键业务决策（最终口径，均为用户确认）

- **广告数据 T+1，次日 10:00（巴西时间）定档**：唯一有延时的数据；广告列只统计到定档截止日（详见 `docs/数据时效说明.md`）。
- **访客**：ML 访客 API 仅提供**按天去重独立访客**（官方文档"访问以每天唯一访问计数"），**无含重复点击的总访客口径**。列名 = **全流量总访问**（来自商品 visits 接口，**不是广告 API**）。预设「近N天」= 最近 N 个完整日（截止巴西昨天）；访客查询恒截断到巴西昨天。**广告 API 无 "Total de visitas" 字段** → 自然访问(估算) = 全流量总访问 − 广告点击。
- **折扣只算「卖家自己设置的优惠」**；平台波动（订单实付/优惠券）不进表格。
- **价格口径**：**原价=挂牌价（prices 端点 standard.amount），现价=折扣价（promotion.amount，实际销售价）**。`/items/{id}` 的 `price` 只是标准价 → 必须额外读 `/items/{id}/prices`。
- **佣金/件 = 最近成交价(last_price) × 佣金率%**；佣金率% = 官方 `listing_prices` 精确费率（类目定制，如 16.5%），订单 `sale_fee` 含支付费（与后台差 ~2%）。
- **流量占比两套口径分开，各自恒=100%**：访客口径（自然访问+广告点击）、销售额口径（自然销售额+广告销售额）；不一致是信号（广告点击占比高但广告销售额占比低 → 广告转化差）。
- **已售** = 区间内已支付订单聚合；**可售库存** = `/items/{id}` 当前可售量。
- 商品分析列布局：**商品信息 / 库存 / 流量·自然vs付费 / 广告·加投决策 / 质量** 五组（收支·盈利组、广告后净得列已按用户要求移除），支持组折叠、显隐列、条件高亮。
- LLM 解读：**已讨论、未接入**（用户说后面再接）。

## 3.5 订单/利润 API 调研结论（2026-08-17 实测，供订单管理模块开发）

- `/orders/search` results **内嵌 `payments[]`**（total_paid_amount / transaction_amount_refunded / taxes / coupon / status）→ 结算/退款直接拿；`/orders/{id}/payments` → 403。
- `/orders/{id}/refunds` → 400；`/returns/search` → **404** → 退货/退款管理页做不了；退款只从 payments 聚合。
- 订单状态枚举实测只有 `paid`/`cancelled` 有效；发货/送达状态从 `/shipments/{id}` 的 `status`/`status_history` 判断。
- 退款单：status=cancelled + refunded>0，paid_amount=0；订单表只增不删(REPLACE upsert)，与 daily_snapshot 重建窗口策略不同。
- 一单多商品极少；订单级金额按 unit_price×qty 占比分摊到行（近似口径）。

## 3.6 广告投放管理 API 调研结论（2026-08-17 实测，已落地广告投放页）

- **ML Product Ads API 是只读监控**，无 create/update/budget 端点（PUT/POST 及 campaign 端点全 404）。
- 本账号为**自动投放模式** → 暂停/调价/加预算只能去 **ML 卖家后台网页**手动操作；看板做**监控+决策建议+手工操作登记**（本地 ad_ops_log 表）。
- 正确路径：`/marketplace/advertising/{site}/advertisers/{adv}/product_ads/ads/search`（Api-Version:2）；`/advertising/...` 官方路径也 404。

## 4. 环境事实（运行/操作）

- 后端 FastAPI 跑在 **8000**（uvicorn，改后端代码需重启）；前端 Vite 跑在 **5173**（改前端热更新，但改完有时要手动刷新）。
- 两个店：`ba05`(显示名 BA05)、`store2`(显示名 AW04)，都 MLB 巴西。店名取 `STORE_NAME`。
- 同步约 6-8 分钟（每日广告 90 次 + 订单物流费 ~580 次）；schema 变更用 db.py 的 `_migrate`（ALTER），加列不需要删库；改 daily_snapshot 列后**要重跑同步**填充。
- 访客列实时查（并发+缓存 30 分钟），访客窗口恒截断到巴西昨天（`backend/app/routers/items.py` `_visits_window`）。

## 5. 调研结论（API 事实，不在代码里）

- **促销 API 对 CBT 卖家官方受限**：`/marketplace/seller-promotions/...` 全部 403。**别再尝试促销接口**。
- **商品级经济学报告接口**（`/metrics/*`、`/meli-report/*`、`/billing_reports` 等）**全部 404** → ML 未对卖家开放商品级"详情成本/净利润/关税"报告接口。
- 买家端页面被验证码挡，无法抓价。
- 订单 `gross_price÷数量`=订单级原价、`unit_price`=实付、`coupon`=优惠券金额；`/items/{id}` 的 `price` 是挂牌价、`original_price` 是划线价（很多商品没设）。
- 数据时效：广告 T+1 定档 10:00 巴西；订单/商品实时；访客 API 仅按天去重独立访客（查询截断到昨日）；token 6 小时过期，同步开头自动刷新。
