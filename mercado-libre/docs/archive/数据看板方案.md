# 美客多多店铺数据看板 — 方案 v2（仿蓝鲸BI · 全面版）

## 1. 定位

- **内部数据看板 · 测试板**：无登录、无权限、无 RBAC，本机/内网自用。
- 目标：仿照「蓝鲸BI」的页面与数据设计，把多个店铺的数据做成可视化网页。
- 数据来源：**全部通过 Mercado Libre API 拉取**，本地快照 + 定时同步。

## 2. 蓝鲸BI 设计解析（已抓包确认）

- 前端：Vue 2 + Vuex + Vue Router（hash）+ Element UI 2.15 + ECharts + axios + lodash。
- 交互：左侧分组菜单 + TopNav + Tags-View 多标签 + 固定 Header + 主题/布局设置；
  顶部全局筛选（多店铺/多市场/站点/币种汇率/时间范围）；表格搜索/显隐列/排序/分页/导出；KPI 卡片 + ECharts。
- 模块（从菜单抓取）：经营总览、商品分析、交易分析、广告流量、利润分析、竞争力分析、
  订单管理、索赔订单、退货管理、库存管理、产品管理、自发货物流、Listing优化、类目预测、选词助手、
  商品详情、店铺详情、商品对比、竞品监控、经营决策、报表、售前/售后消息、评价管理、店铺声誉、配置、系统管理。

## 3. 现状盘点

- 2 店铺：`ba05`（BA05 / MLB）、`store2`（AW04 / MLB）。
- 已有代码可复用为「采集层」：`src/store.py` `src/auth.py` `src/client.py` `src/atoms/products.py` `src/atoms/export.py`。
- 现有字段（19，变体/SKU 粒度）：
  `item_id, title, seller_sku, gtin, price, available_quantity, sold_quantity, currency_id,
  total_visits, performance_score, performance_level, has_ads, ad_clicks, ad_impressions, ad_ctr, ad_cost, ad_roas, variation_id, attributes`

## 4. 蓝鲸面板 → ML API 端点映射（核心）

| 蓝鲸面板 | ML API 端点 | 说明 / 状态 |
|---|---|---|
| 商品分析/列表/详情 | `GET /users/{id}/items/search` + `GET /items/{id}` | ✅ 已有（含 variations/attributes/pictures/sale_terms） |
| 访客流量 | `GET /items/{id}/visits/time_window?last=30&unit=day` | ✅ 已有 |
| Listing 优化 | `GET /item/{id}/performance` | ✅ 已有（0–100 评分 + 改进建议） |
| 广告流量 | `GET /advertising/advertisers` + `GET /marketplace/advertising/{site}/advertisers/{adv}/product_ads/ads/search?metrics=clicks,prints,ctr,cost,roas` | ✅ 已有（品牌广告另加 brand_ads 端点） |
| 交易分析 / 订单管理 | `GET /orders/search?seller={uid}&order.status=&order.date_created.from=&order.date_created.to=` + `GET /orders/{id}` | 🆕 |
| 订单支付/结算 | `GET /orders/{id}/payments` | 🆕 |
| 自发货打单 / 物流 | `GET /shipments/{id}` + `GET /shipments/{id}/labels` + `GET /shipments/{id}/tracking` + `GET /orders/{id}/shipments` | 🆕 |
| 售前/售后消息 | `GET /questions/search?seller_id={uid}&status=&item=` | 🆕 |
| 评价管理 | `GET /reviews/search?seller_id={uid}` + `GET /items/{id}/reviews` | 🆕 |
| 店铺声誉 | `GET /users/{uid}` → `seller_reputation`（level_id / power_seller_status / metrics: sales, claims, delayed_handling_time, cancellations） | 🆕 |
| 库存管理（当前量） | `GET /items/{id}` → `available_quantity`（商品 + 变体） | 🆕 |
| 类目预测 | `GET /sites/{site}/domain_discovery/search?q={title}` + `GET /categories/{id}/attributes` | 🆕 |
| 选词助手 | `GET /sites/{site}/trends/search` + `GET /sites/{site}/search?q=` | 🆕 |
| 竞品监控 | `GET /items/{竞品id}`（公开）+ `GET /sites/{site}/search?seller_id=&q=` | 🆕 |
| 利润分析 | 计算：订单收入 − 平台佣金 − 广告花费 − 商品成本 − 物流费 | ⚠️ 佣金取 sale_terms/类目费率，成本手工录入 |
| 报表 / 导出 | 本地库聚合 + `src/atoms/export.py` | 🆕 |
| 商品对比 / 店铺详情 | 本地库两商品/两店对比 | 🆕 |

### ML API 给不了、需手工或本地积累的（蓝鲸同款处理）

| 数据 | 处理方式 |
|---|---|
| 商品成本 | 手工录入（蓝鲸「成本管理 / 批量上传成本」） |
| 汇率 | 第三方或手工（蓝鲸「固定汇率 + 当日市场汇率」） |
| 历史趋势（销量/库存/排名/访客随时间） | ML 不给历史，本地**每日快照**累积 |
| 竞品访客/广告 | 拿不到，仅竞品公开的 price / sold_quantity / rating / status |

```
│   订单管理 / 物流 / 消息 / 评价 / 店铺声誉 / 库存 / 报表 / 对比 │

│                  后端 (Python / FastAPI)                        │
│  routers: overview / products / orders / shipments / questions  │
│           reviews / reputation / ads / reports / sync / export  │
│  Pydantic 模型（各域 schema）                                    │
└─────────────────────────────┬─────────────────────────────────┘
                              │ 读快照
┌─────────────────────────────▼─────────────────────────────────┐
│              SQLite 本地库（多表快照）                          │
│  product_variation / order / order_item / shipment / question   │
│  review / reputation / snapshot(每日趋势) / cost(成本配置)      │
└─────────────────────────────┬─────────────────────────────────┘
                              │ 定时 / 手动触发同步
┌─────────────────────────────▼─────────────────────────────────┐
│          数据采集层（复用 + 扩展现有 src/）                      │
│  products(已有) + orders / shipments / questions / reviews /    │
│  reputation / trends / competitor 等新 collector                │
└─────────────────────────────┬─────────────────────────────────┘

```

**同步策略**：每个 collector 单独跑（商品、订单、物流、消息、评价、声誉互不阻塞），
手动「一键刷新」+ 可选 APScheduler 定时；结果写 SQLite，前端只读快照。

## 6. 技术选型

| 层 | 推荐 | 备选 |
|---|---|---|
| 后端 | **FastAPI + uvicorn**（异步、自动 /docs、Pydantic） | Flask |

## 7. 数据模型（按域分表）

### product_variation（变体/SKU 一行）
`store, item_id, variation_id, title, seller_sku, gtin, price, available_quantity, sold_quantity,
currency_id, status, category_id, listing_type_id, condition, permalink, pictures, sale_terms,
total_visits, performance_score, performance_level, has_ads, ad_clicks, ad_impressions, ad_ctr, ad_cost, ad_roas,
attributes, updated_at`

### order
`id, store, status, total_amount, currency_id, pack_id, date_created, date_closed, buyer_id, buyer_nickname, updated_at`
### order_item
`order_id, item_id, title, quantity, unit_price, currency_id, sale_fee`

### shipment
`id, order_id, store, status, mode, carrier, tracking_number, cost, currency_id,
date_created, date_shipped, date_delivered, updated_at`

### question
`id, store, item_id, text, status(UNANSWERED/ANSWERED/...), date_created, from_id, from_nickname, answer_text, answer_date`

### review
`id, store, item_id, rating, title, content, status, date_created`

### reputation
`store, level_id, power_seller_status, metrics(JSON), updated_at`

### snapshot（每日趋势，供历史曲线）
`store, item_id, date, price, available_quantity, sold_quantity, total_visits, performance_score, updated_at`

### cost（成本配置，手工）
`store, item_id/sku, product_cost, shipping_cost, updated_at`

## 11. 分阶段实施

- **P0（商品域，先跑通）**：FastAPI + SQLite + 商品同步接口；前端骨架（仿蓝鲸布局）+ 经营总览 + 商品列表 + 详情 + 导出。
- **P1（交易/客服域）**：订单、物流、消息、评价、声誉、广告 各 collector + 对应页面。
- **P2（分析/决策域）**：每日快照趋势、利润分析（成本录入）、竞品监控、类目预测、选词助手、报表下载中心。

## 12. 需要你确认 / 可能要改的点

1. **前端框架**：Vue3 + Element Plus（最贴近蓝鲸，推荐）还是 React + Ant Design？
2. **MVP 优先级**：按上面 P0→P1→P2 的顺序推进可以吗？还是想先做某几个特定模块（比如先做订单/交易分析）？
3. **存储**：SQLite 起步（推荐）还是直接 MySQL/Postgres？
4. **同步方式**：手动「一键刷新」+ 可选定时任务（推荐）？定时频率想要多少（每 1 小时 / 每天）？
5. **利润分析**：商品成本要手工录入（像蓝鲸成本管理），这块先做吗，还是 P2 再说？
6. **历史趋势**：确认要靠「每日快照」累积（ML 不给历史），你接受从接入那天才开始积累趋势吗？
7. **币种/汇率**：当前两个店都是巴西 BRL，先固定 BRL、字段预留，等有多站点再加汇率？
