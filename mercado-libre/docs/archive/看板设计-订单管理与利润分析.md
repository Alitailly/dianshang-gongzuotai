## 1. 订单管理（#/orderList）

### 1.1 定位
订单明细管理页：按 日期/店铺/状态/关键词 筛订单，看每单的钱（实付/佣金/物流/结算/退款）和物流（状态/方式/运单/收货人）。数据**实时**（订单不延时）。

### 1.2 页面布局（仿蓝鲸）

**统计条（8 卡，随筛选联动）**：订单数 / 销量 / 销售金额 / 结算金额 / 退款金额 / 平台佣金 / 物流费 / 客单价(=销售金额÷订单数)。

**状态 Tab**（点击过滤，非 order.status 枚举，用组合条件）：
- 全部
- 待发货：`order.status=paid` 且 `shipment_status ∈ {handling, ready_to_ship}`（或无 shipment）
- 已发货：`shipment_status = shipped`
- 已送达：`shipment_status = delivered`
- 已取消：`order.status = cancelled`
- 有退款：`refunded_amount > 0`

**筛选行**：店铺下拉（BA05/AW04）｜ 日期范围（默认近 30 天，picker 同全局规则）｜ 关键词（订单号/SKU/商品标题）｜ 导出 CSV。

**表格列（20 列，组折叠同商品分析风格）**：

| 组 | 列 | 来源 |
|---|---|---|
| 订单信息 | 订单日期 / 订单号(可复制) / 店铺 / 订单状态(中文映射) | order.date_created / id / store / status |
| 商品 | 商品(标题+item_id) / SKU / 数量 | order_items |
| 钱 | 实付单价 / 销售金额(=单价×数量) / 优惠金额(=(gross_price−unit_price)×数量) / 平台佣金(=sale_fee×数量) / 物流费(分摊) / 结算金额(分摊 paid_amount) / 退款金额(分摊 refunded) | ✅ 列表已有 |
| 物流 | 物流状态(中文) / 物流方式(tracking_method) / 运单号 / 配送类型(logistic_type) | /shipments/{id} |
| 收货 | 收货人 / 城市·州 / 邮编 | receiver_address |

**默认排序**：日期倒序（最新在前）。

**高亮规则**：退款金额>0 → 红；待发货 → 橙；已送达 → 绿；取消 → 灰。

### 1.3 数据表设计（新增 `orders` 表）

```sql
CREATE TABLE orders (
  store TEXT NOT NULL,
  order_id TEXT NOT NULL,
  item_id TEXT NOT NULL,
  variation_id TEXT,
  seller_sku TEXT,
  date_created TEXT,          -- 订单时间（ML 本地）
  status TEXT,                -- paid / cancelled / ...（以实测枚举为准）
  quantity REAL,
  unit_price REAL,            -- 实付单价
  gross_price REAL,           -- 订单级原价（单件）
  sale_fee REAL,              -- 平台佣金（单件）
  paid_amount REAL,           -- 订单结算金额（实际支付）
  refunded_amount REAL,       -- 订单退款金额
  taxes_amount REAL,
  coupon_amount REAL,
  payment_method TEXT,        -- visa / pix / ...
  shipment_id TEXT,
  shipment_status TEXT,       -- handling/ready_to_ship/shipped/delivered/...
  tracking_number TEXT,
  tracking_method TEXT,       -- Sedex / ...
  logistic_type TEXT,         -- drop_off / ...
  receiver_name TEXT,
  city TEXT, state TEXT, zip_code TEXT,
  PRIMARY KEY (store, order_id, item_id)
);
CREATE INDEX idx_orders_date ON orders (date_created);
CREATE INDEX idx_orders_store ON orders (store);
CREATE INDEX idx_orders_sku ON orders (seller_sku);
```

> 订单表**只增不删**（REPLACE 按主键 upsert），越攒越全；与 daily_snapshot 的"重建窗口"策略不同。

### 1.4 采集设计（并入同步）

1. `orders/search` 分页全量拉窗口内订单（**不加 status 过滤**，把 cancelled/退款单也收进来；窗口=同步窗口 90 天，与现有一致）。
2. 每单并发（ThreadPoolExecutor 8 workers，复用访客并发模式）调 `/orders/{id}/shipments` 或 `/shipments/{id}` 取 物流状态/方式/运单/收货地址。
3. 拆行：每 `order_items[]` 一行；订单级金额（paid_amount/refunded_amount/coupon）按 `unit_price×qty ÷ Σ(unit_price×qty)` 分摊。
4. **不 DELETE**：`INSERT OR REPLACE` 按 (store, order_id, item_id)。
5. 时间估算：750 单 → 15 次分页 + 750 次 shipments ÷ 8 并发 ≈ **+1~2 分钟**（当前同步 6-8 分钟可接受）。

### 1.5 口径说明
- **销售/收入口径不变**：daily_snapshot 仍只收 `status=paid` 订单；取消/退款单只进 orders 表，**不污染商品分析/经营总览的销售数字**。
- 结算金额 = `paid_amount`；退款金额 = `Σ payments[].transaction_amount_refunded`（口径：全额退款单）。

## 2. 利润分析（#/tradeAnalyze/historyAnalyze）

### 2.1 定位
蓝鲸核心页：店铺/商品维度的 收入−平台费−广告−物流−采购−头程−其他−退款−税 = 净利润。**毛利 ✅ 现有数据可算；净利 ✋ 等成本录入**。

### 2.2 公式体系（写进后端，逐项标注来源）

```
毛利     = 销售额 − 平台佣金 − 广告费 − 物流费            ← ✅ 全部现有（repository 已有）
采购成本 = purchase_cost × 销量                          ← ✋ cost_config 录入
头程物流 = first_leg_cost × 销量                         ← ✋ cost_config 录入
其他成本 = other_cost × 销量                             ← ✋ cost_config 录入
退款金额 = 区间内 Σ refunded_amount                      ← 🆕 orders 表采集
税       = 可配置（默认关闭=0；口径 ⚠️ 待定：销售额×税率 或 净利×税率）
净利润   = 毛利 − 采购成本 − 头程 − 其他 − 退款 − 税
净利润率 = 净利润 ÷ 销售额 × 100
```

### 2.3 数据表设计（新增 `cost_config` + `settings`）

```sql
CREATE TABLE cost_config (
  store TEXT NOT NULL,
  item_id TEXT NOT NULL,
  variation_id TEXT,
  seller_sku TEXT,              -- 便于按 SKU 匹配录入
  purchase_cost REAL DEFAULT 0, -- 采购成本/件 (BRL)
  first_leg_cost REAL DEFAULT 0,-- 头程物流/件 (BRL)
  other_cost REAL DEFAULT 0,    -- 其他成本/件 (BRL)
  updated_at TEXT,
  PRIMARY KEY (store, item_id, variation_id)
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);
-- 预留：tax_rate_pct / tax_base(销售额|净利润) / 汇率 BRL→RMB
```

### 2.4 成本录入 UI（✋ 手工，利润分析前置）
- 入口：利润分析页"成本管理"按钮 → 弹窗/抽屉。
- 列表：按店铺 + 关键词（SKU/标题）筛商品，行内编辑 采购/头程/其他 三列，保存即写 cost_config。
- **批量导入**：CSV（SKU, 采购成本, 头程成本, 其他成本）上传，按 seller_sku 匹配 upsert（无 SKU 的标红提示）。
- 高亮：`sold_quantity>0` 且 `purchase_cost=0` 的商品标灰"缺成本"，避免净利润虚高。

### 2.5 页面布局（仿蓝鲸）

**KPI 卡（6）**：销售额 / 毛利 / 净利润 / 净利润率 / 总成本(采购+头程+其他) / 平台费用合计(佣金+广告+物流)。带环比。

**店铺维度**：小卡片/小表（每店 销售额/毛利/净利润/净利润率）。

**商品维度大表（组折叠）**：

| 组 | 列 |
|---|---|
| 商品信息 | 商品(标题+ID) / 店铺 / SKU / 销量 / 销售额 |
| 平台费用 | 平台佣金 / 广告费 / 物流费 / 毛利 |
| 成本(手工) | 采购成本 / 头程物流 / 其他成本 / 总成本 |
| 利润 | 退款金额 / 税 / 净利润 / 净利润率 |

- 排序默认：净利润 desc。
- 高亮：净利润<0 → 红；缺成本（sold>0 且 purchase=0）→ 灰标。
- 筛选：店铺 / 日期范围（复用全局 picker）/ 关键词 / 只显示缺成本。

### 2.6 接口清单（新增）
- `GET /api/profit/summary?store=&date_from=&date_to=` → KPI + 店铺维度
- `GET /api/profit/items?store=&keyword=&page=&page_size=&sort_by=&order=&date_from=&date_to=` → 商品表（list_items 聚合 + cost_config LEFT JOIN + orders 退款聚合）
- `GET/PUT /api/costs`（单个 SKU 或批量 upsert）、`GET /api/costs/import`（CSV）
- `GET/PUT /api/settings`（税率等）

## 4. 风险与待实测 ⚠️
- 税的口径（巴西 ICMS/简易税制、sale_fee 是否含税）→ 默认关闭，用户可配。
- 部分退款单（paid 且 refunded<paid）实测样本未出现，若出现需定分摊口径。
- 物流费两处口径：`/shipments/{id}/costs` 的 `senders[].cost`（现有采集） vs shipment 的 `base_cost` → 订单表用现有 costs 口径，保持一致。
- 一单多商品分摊为近似口径，样本极少，先按占比分摊，后续校准。
