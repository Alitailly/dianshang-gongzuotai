> 定档版（2026-08-19）。所有字段"怎么取、怎么算"的唯一权威说明。改动口径必须同步更新本文档 + `docs/06-逻辑疑点-待确认.md`。

## 0. 数据时效一览（哪些实时、哪些 T+1）

| 数据 | 时效 | 来源 |
|---|---|---|
| 商品标题/现价/原价/可售库存 | ✅ 实时 | `/items/{id}` + `/items/{id}/prices` |
| 订单（已售/销售额/佣金/物流费） | ✅ 实时 | `/orders/search` + `/shipments/{id}/costs` |
| 访客（全流量总访问） | ⚠️ 按天去重 | `/items/{id}/visits`（=后台 Visitas únicas，**查询恒截断到巴西昨天**） |
| 体验分 | ⚠️ 按天更新 | `/items/{id}/performance` |
| 广告（花费/点击/曝光/收入/ROAS/ACOS） | ❌ **T+1** | 广告报表 API，**只统计到定档截止日** |

> 唯一有延时的数据是**广告（T+1，次日巴西 10:00 定档）**；其余实时/按天。
> 实现：`src/timeutil.py` → `br_latest_finalized_date()`；接口 `GET /api/meta/data-status` 返回 `br_today` / `latest_finalized_date` / `earliest_date`。

### 看板区间口径（2026-09-11 起）

看板前端查询一律遵守下列两条，保证「订单窗口 = 广告窗口」，派生列（结算 / 自然销售额 / 各类占比 / 保本ROAS）才准确：

1. **区间结束日截到定档日**：可选统计截止日 = `min(巴西昨天, 广告定档截止日)`。自定义区间结束日若晚于该值会被自动拉回；预设「近 N 天」以该值为终点往前推 N 个完整日。
   - 代价：巴西 0:00–10:00（北京 11:00–21:00）广告尚未定档，区间结束日落在**前天**。
   - 实现：`frontend/src/composables/useDataRange.ts` 的 `statsEndDate` / `getRange()`。后端 `repository._ad_cap()` 为二道防线（接口被直接以 `date_to > 定档日` 调用时仍截断广告聚合）。
   - 修复前症状：汇总卡片按定档日截断、趋势图却含未定档日 → 同一页两处广告花费对不上（实测差 679.62）；商品级「自然销售额」= 订单全窗 − 广告截断窗 → 混窗，实测 17/68 个商品偏差。
2. **投放商品 = 区间内有广告数据**：区间内 `曝光>0 或 花费>0 或 点击>0` 的商品。广告流量页列表 `total` 与汇总 `ad_items` 同此口径（`backend/app/routers/ads.py` 固定传 `ad_active="1"`）；商品分析页**不过滤**（列全店商品用于自然/付费对比）。

## 1. 商品字段口径（product_variation → 看板/飞书"属性列"）

| 列 | 取值 | 说明 |
|---|---|---|
| 现价 | `prices` 端点 `type=promotion` 的 `amount` | **实际销售价**（折扣价）；无促销=标准价 |
| 原价 | `prices` 端点 `type=standard` 的 `amount`（= `/items/{id}` 的 `price`） | 挂牌价/划线价；没设置 → 原价=现价 |
| 变体 | 商品下变体行数 COUNT | 属性列 |
| 佣金率% | `GET /sites/{site}/listing_prices` 的 `sale_fee_details.percentage_fee` | **官方精确费率**（按 类目+价格+物流，如 16.5%，与后台一致）；无精确值 → 按 listing 类型（gold_special 11% / gold_pro 16%） |
| 佣金/件 | 现价 × 佣金率% ÷ 100 | 飞书用当天现价；看板用最近成交价 |
| 平台运费 | 按承担方：seller→`base_cost`(平台成本价)；buyer(买家付)→0；meli(包邮)→0 | 见「运费口径」 |
| 实际收入/件 | 现价 − 佣金/件 − 平台运费 | |
| 体验分 | `/items/{id}/performance` | |
| 广告(有/无) | 当前是否有广告活动 `has_ads` | 实时状态，套用到该商品所有历史行 |
| 上架日 | `date_created` | **决定飞书从哪天开始显示该商品** |

⚠️ **可售库存 = 当天快照（daily_stock，2026-08-19 启用）**：每天同步时把每个商品当天的 库存/现价/原价/体验分/佣金率/广告 等聚合值存一份。
- **可售库存**：历史行显示**当天快照值**；**快照启用前的日子（历史库存不可知）→ 显示空白**。
- **其余属性列**（现价/原价/体验分/佣金率%/佣金件/平台运费/实际收入件/变体/广告有/无）：优先当天快照，**无快照回退当前值**（能读到的就显示）。
- 广告指标（点击/曝光/花费/收入/ROAS 等）来自订单/广告历史，一直可靠显示，不受快照影响。
- 今天这行仍每次同步刷新为最新。

## 2. 订单字段口径（daily_snapshot，按 商品×日期 聚合）

数据源：`/orders/search`（paid 订单，近 N 天）+ `/shipments/{id}/costs`（发货单卖家物流成本）。

```
销售额  = 订单 total_amount × (该商品金额 ÷ 订单总金额)     ← 多商品单按金额占比分摊
佣金    = Σ(sale_fee × qty)                                ← 订单行级销售费用（不含固定费，见疑点#4）
物流    = 发货单卖家运费 × (该商品金额 ÷ 订单总金额)          ← 按金额占比分摊（口径待确认，见疑点#1）
已售    = Σqty
订单数  = 去重订单数
成交价  = 当日最新一笔的 unit_price / full_unit_price(gross_price÷qty) / coupon_amount
折扣总额 = Σ gross_amount − Σ 销售额（所有渠道让利合计，含平台补贴）
```

> 销售额口径 = `order.total_amount`（含买家运费），与后台「Desempenho do seu anúncio」一致。

## 3. 广告字段口径（daily_snapshot，按天）

数据源：`/marketplace/advertising/{site}/advertisers/{advertiser_id}/product_ads/ads/search`
（metrics：`clicks, prints, ctr, cost, roas, total_amount, acos`）。

```
广告点击/曝光/花费/收入 = clicks / prints / cost / total_amount
ROAS / ACOS / CTR      = 报表直接返回的 roas / acos / ctr
```

**T+1 处理**：定档截止日之后的行 → 广告列在**飞书侧显式置空**（batch_update 只更新传入字段，省略字段不清空 → 必须显式写 None），避免"实时数据对、广告数据错"。

## 4. 折扣与优惠口径（纯卖家口径）

- **核心原则**：只算**卖家自己设置的优惠**（原价 vs 现价），平台波动（实付价/优惠券/平台补贴促销）**不进折扣计算**——平台出资不影响卖家利润。
- `折扣率% = (1 − 现价 ÷ 原价) × 100`（原价 > 现价才计算，否则 0）
- `优惠原因` = 促销价 / 平台活动 / 卖家划线价（原价>现价）/ 空
- `折扣总额 = Σ(gross_amount) − Σ(销售额)`（所有渠道让利合计，含平台补贴与自己让的；不依赖划线价）
- 订单实付价（unit_price）只用于销售额/结算口径，**不参与折扣计算**。

| meli（平台包邮） | 0 | 「包邮」 |

## 6. 派生列公式（飞书每日行 + 看板区间，同一套公式）

设：`销售额`=当日/区间订单销售额，`广告收入`=广告报表 total_amount，`广告花费`=cost，
`全流量总访问`=visits 按天去重独立访客，`佣金`/`物流`=当日聚合。
（公式表由代码生成，勿手改；来源 `backend/app/routers/bitable.py` DERIVED_FORMULAS）

| 列 | 公式 |
