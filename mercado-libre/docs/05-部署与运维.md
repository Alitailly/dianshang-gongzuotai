# 05 · 部署与运维

> 定档版（2026-08-19）。定时任务跑在后端进程内，**后端必须常开**。

## 1. 环境要求

- Python 3.9+（本项目用 `.venv`）、Node 18+（前端开发时可不开，看板数据由后端 API 提供）
- 依赖：`pip install -r requirements.txt`（含 fastapi / uvicorn / requests / python-dotenv / apscheduler）
- 磁盘：`data/dashboard.db`（SQLite，当前 ~几百 KB，长期累积每日快照，量级很小）

## 2. 启动后端（常开）

### 方式 A：nohup（简单）

```bash
cd /Users/alitailly/mercado-libre-project
nohup .venv/bin/python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 \
  >> data/backend.log 2>&1 &
```

### 方式 B：systemd（推荐服务器）

`/etc/systemd/system/ml-dashboard.service`：

```ini
[Unit]
Description=Mercado Libre Dashboard (FastAPI)
After=network.target

[Service]
WorkingDirectory=/path/to/mercado-libre-project
ExecStart=/path/to/mercado-libre-project/.venv/bin/python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ml-dashboard
```

> `Restart=always` 保证宕机后自动拉起；拉起时若错过当天定时点会自动**开机补跑**（见 docs/03 §3）。

## 3. 定时任务（无需额外配置）

| 时间点（自动） | 说明 |
|---|---|
| 北京 08:50 / 13:50 | ML 增量拉取 + 飞书全区间同步 |
| 巴西 10:20（=北京 21:20） | 广告定档后补全昨日广告列 |

- 状态标记：`data/.daily_update_marker`（最近成功日期，勿手动改）
- 日志：进程 stdout（nohup 则 `data/backend.log`），关键行带 `[scheduler]`

## 4. 日常运维命令

```bash
# 健康检查
curl -s http://127.0.0.1:8000/api/health

# 手动全量同步（ML→SQLite，默认 90 天）
curl -X POST "http://127.0.0.1:8000/api/sync"
# 增量同步（最近 N 天）
curl -X POST "http://127.0.0.1:8000/api/sync?days_back=4"

# 手动飞书同步 / 回填
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily"
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily/backfill?days_back=7"

# 校验飞书（建议每次大动作后跑）
curl -X POST "http://127.0.0.1:8000/api/export/bitable/daily/verify"
# 期望输出：0 缺失 / 0 多余 / 0 值差 → OK；出现 MISMATCH 看 diffs 字段定位
```

## 5. 故障排查

| 症状 | 排查 |
|---|---|
| 同步失败 `error: …` | 看 `GET /api/sync/status` 的 error；多为 ML token 过期（自动刷新失败）或网络。重试；长期失败检查 `stores.d/*.env` token |
| 定时任务没生效（今天该同步的数据没更新） | 先看进程日志的 `[scheduler]` 行：① 后端是否常开（定时跑在进程内，重启会错过已过的时间点，靠开机补跑）；② 是否 **ML 限流 429**（日志 `429 Too Many Requests`）—— 客户端已自动重试 3 次，仍失败会记录并等下一次定时点/开机补跑；限流通常是短时间请求过多，稍后自动恢复 |
| 飞书没更新 | ① 检查后端进程是否常开、日志有无 `[scheduler]` 报错；② 手动跑 `/daily` + `/verify` 定位；③ 确认 `feishu.env` 的 APP_TOKEN 指向正确 base |
| 飞书表报错 1254034（删最后一个表） | 一个 base 至少留 1 个子表；重建前先建临时占位表 |
| 飞书字段/记录写入报错 | 检查 `bitable:app` 权限是否生效（改权限后需发布版本）；batch ≤500/次 |
| verify 出现「可售库存/现价」差值 | 属性列是当前值：若两次同步之间库存/价格变了，历史行会刷新 —— 属预期；跑一次全区间同步即一致 |
| 数据日期停在昨天 | ~~正常~~（旧设计）：现在同步范围**含巴西今天**（今天实时数据：已售/库存/现价；广告列未定档为空、次日定档后自动补）。若某天没出现，先手动跑 `/daily` + `/verify` 定位 |

## 6. 数据备份

- 核心数据 = `data/dashboard.db`（SQLite，单文件）。定期 `cp` 到备份目录即可；或 `sqlite3 data/dashboard.db ".backup data/backup-$(date +%F).db"`。
- 飞书侧只是展示层，丢了可随时从 SQLite 全量重建。
- 店铺凭证：`stores.d/*.env`、`feishu.env`（含密钥，备份时注意保密）。
